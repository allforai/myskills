# 场景 P2 — 催款小工具（体验质量门 · design 阶段）

你是 fresh-context 评审者，执行 `experience-quality-critique`，`stage: "design"`。你没有写过下面任何产物。为了这次演练，Input Contract 里的产物内容已摘录在下面；当作你已读完这些文件，所有必需输入都存在。不需要生成 HTML 和 review doc，只输出 JSON 里的 `lenses`、`findings`、`gates`、`overall_recommendation` 四段（可精简字段值，但字段要在），外加不超过 6 行的说明。

**已确认的体验方向**（product-concept.json requirements，topic=experience-direction，status=confirmed）
- 表述："极简：自由设计师打开就能催到钱，不要让他学任何东西。"
- acceptance：① 从打开到发出第一条催款不超过 3 步；② 首页只有一件事；③ 不出现设置向导。
- who：独立接单的设计师；circumstance：月底对账时发现有几笔没收到。

**bootstrap-profile**：experience_priority.mode = consumer。

**job-story-spec 摘要**：当月底我发现有客户没付款时，我想不尴尬地提醒对方，好把钱收回来又不伤关系。

**user-flow-spec 摘要**（主流程 F1 催款）
1. 首页：直接列出"未付款"卡片，每张一个按钮「催一下」。
2. 点「催一下」：系统用默认话术立即通过邮件发给客户。没有预览、没有确认；发出后卡片角标变为"已催"。
3. 结束。
- 设计说明（作者写的）："为满足 3 步以内，去掉了话术预览与确认页；去掉了'选择语气（礼貌/正式/强硬）'；去掉了客户联系人选择，统一发给发票上的第一个邮箱。话术如需修改，可在 设置 > 高级 > 模板 里改全局默认。发错的情况预计很少，如发生由用户自行邮件向客户解释。"
- 次流程 F2 新建发票：4 步，略。

**screen-requirements-spec 摘要**
- S1 首页：states = empty（"没有未付款，真好"）/ loading / error / list。卡片字段：客户名、金额、逾期天数、按钮。
- S1 卡片 states：default / sending / sent（角标"已催"）/ failed（"发送失败，重试"）。
- S5 设置 > 高级 > 模板：一个多行文本框，变量 {{客户名}} {{金额}}。

**settings spec**：全部 items 的 audience = end-user。无 endpoint 类设置。
