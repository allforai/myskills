# meta-skill：产品决定中断续接与旧基准安全接入

> 修订 v2；用户以 $implement 并发批准执行。原位更新原票，保留原验收要求和同步后增量。

## Parent

https://github.com/allforai/myskills/issues/8

## What to build

让产品确认可以中断后继续，并让旧项目安全接入已确认基准机制。系统复用有依据的历史决定，仅询问未决或新受影响的内容；没有确认来源的旧代码推断不能伪装为已批准需求。

本票保留原第 3/6 个纵向切片，包含必要的合同、交互／执行接入与行为测试，不拆成横向层次任务。只实现本票边界，遵守父规格的范围限制。

## Acceptance criteria

- [ ] 在意图讨论中断后重新 bootstrap，已确认决定、理由、调整／删除历史和明确排除范围完整恢复，不重复完整访谈。
- [ ] 未回答的问题保留待决状态；中断或旧文件存在不产生隐式确认。
- [ ] 旧 concept／baseline 有可信确认记录时按相关范围复用；没有确认来源时标为待核实，只询问本次任务所需缺口。
- [ ] 旧基准接入不自动覆盖历史，不因为文档缺确认字段就把局部功能升级为全产品重塑。
- [ ] 相关未决依赖保持不可执行，无关工作不会仅因这个问题被失效；显式范围排除与未回答严格区分。
- [ ] 确认在 bootstrap 交互阶段完成，并作为 decision inputs 交给执行；无人值守阶段不新增访谈、不捏造回答，不改造现有人审机制。
- [ ] 用户补齐相关决定后，依赖工作可恢复进入规划／执行，无需重做已完成确认。
- [ ] 以中断—重入—补齐决定的端到端场景，以及有确认记录／无确认记录的旧基准场景验证；同时检查两端 readiness 结果和用户提问行为，不仅检查字段存在。
