### Failure Pattern

Three engine/planning defects seen in one /run: (1) wide parallel waves: check_artifacts freshness reports invalid ('Inputs changed during freshness evaluation: observed-input-dependencies.json') because siblings write shared freshness state; four finished nodes with valid evidence were returned hard_fail and left without transition_log entries, which validate_bootstrap then rejects (transition_log_missing_for_delivered_nodes). The gate should retry after the wave settles or serialize gate evaluation. (2) validate_bootstrap/readiness do not reject two nodes declaring the same exit_artifacts path; the later publisher stales the earlier node and its closure. (3) a repair node's hard dependency that reads the files the repair edits makes every delivery unmeasurable (unmeasured_repair_delivery) until the loop budget is spent.

### Expected Behavior

The meta-skill should record or repair this class of workflow issue without exposing project-specific information.

### Suggested Fix

Update the relevant skill, bootstrap rule, validator, or orchestrator helper so future projects do not hit the same failure pattern.
