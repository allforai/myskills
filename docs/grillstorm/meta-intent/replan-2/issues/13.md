- [ ] 规划阶段识别相关事实文档、产品决定、Node-spec／依赖和验证责任，局部改动不要求重新 bootstrap 整个产品。

- [ ] 已批准的产品变化按记录同步到基准；实现不能自行覆盖用户意图，也不重复询问已有且仍适用的决定。
- [ ] 产品源码、确认基准、必需文档或验收证据任一不一致时，相关任务不能标记完成，即使代码构建或测试局部通过。
- [ ] 不一致形成明确差异与修复责任，回到责任任务修复后重新同步并重验，不能只写一条警告便宣称闭环。
- [ ] 未知产品决定不能由无人值守执行补造；相关工作报告受阻并交回交互阶段处理，遵守已有有限重试与失败报告机制。
- [ ] 修复完成后，新证据绑定当前输入并恢复相关完成状态，无关工作保持有效。
- [ ] 用完整局部功能 fixture 验证文档遗漏拒绝完成、纠正后通过、已批准产品变化传播，以及受阻后恢复；两端使用相同产品权威规则和外部行为判据。
