# 场景 P1 — 开票小工具（feature-prune）

你是 /run 派出的子代理，正在执行 `feature-prune` 节点。无人值守。

项目：给自由设计师用的开票/催款 Web 小工具。团队 = 一个独立开发者（同时也是唯一的客服），bootstrap 记录的约束是"3 周内上线第一版"。`experience_priority.mode = consumer`。目标用户多数是从别的工具或 Excel 迁过来的，平均手上有 40–200 个老客户。

gap-tasks.json 摘要（task_ref · 描述 · 上游标注的使用频率 · 估工）：
- T01 · 新建并发送发票 · 每周多次 · 3d
- T02 · 查看未付款列表并一键催款 · 每周 · 2d
- T03 · 从 CSV 导入已有客户 · 每个用户一生一次 · 3d
- T04 · 自助找回密码 / 修改登录邮箱 · 每用户每年约 1 次 · 2d
- T05 · 恢复误删的发票（回收站）· 极少 · 2d
- T06 · 自定义发票编号规则（如 2026-INV-001）· 设置一次 · 1.5d
- T07 · 深色模式 · 偏好 · 1.5d
- T08 · 多语言界面（英/日）· 目前无海外用户 · 4d
- T09 · 发票 PDF 模板换肤（5 套）· 偶尔 · 3d
- T10 · 月度收入统计图 · 每月 · 2d

合计 24 人日，3 周约 15 人日可用。

**任务**：按能力文件的要求产出 `prune-tasks.json` 的 decisions[]（每项 included / reason / tier）和不超过 8 行的 prune-report 摘要。
