# 镜头泄漏点扫描指南

可选视觉验收：用户选中 UI facet 时加载 visual/visual-acceptance.md。
以用户确认的视觉/交互基线对照真实 App 截图和动态证据；源码仅辅助。

泄漏点 = **如果 X 真做完了就不该长这样的细节**（侧信道信号），不是"看起来没做完"。
扫描浅而快：只找值得问的线头，绝不自己下结论——结论必须等实测官的证据。
每轮只扫当前面，不做全库深扫。

**零命中不是泄漏点，是待证问题。** grep 不到某个名字，最常见的原因是你的搜索姿势
不对（路径扫窄了、大小写、命名变体、配置在另一层目录），不是它不存在。先换姿势
再扫一遍；仍然存疑就把"X 到底存在吗、在哪生效"直接做成问题牌交给实测官全库取证——
让证据说它不存在，而不是你的 grep 说。

| 镜头 | 采样口 | 泄漏点示例 |
|------|--------|-----------|
| 需求覆盖 | 需求基准 ↔ 台账/代码对账 | 需求说"退款可追踪"，全库 grep 不到 refund_id；某需求无任何任务/测试引用 |
| 集成缝隙 | 接口两侧形状对比 | 生产者写 snake_case、消费者读 camelCase；配置项定义了无人读；A 调的端点 B 没注册 |
| 需求跑偏 | 需求原文 ↔ 实现语义 | 需求"离线可用"，实现"断网弹提示"；验收测的是函数存在而非行为对 |
| 细节质量 | 状态空间穷举 | 只有 happy path 的测试名；错误分支裸 500；空列表/超长输入/并发无处理痕迹 |
| 契约 census（死端点）| 契约面全集逐个查调用点（覆盖法，不吃需求基准）| 定义了却零生产调用点的 RPC/handler/hook = 假成功烟枪；用户操作显示"成功"却追不到 server 调用；某端点只有生产者/消费者一侧接线；翻译 key 在默认语言有、某语言没有（运行时静默回落，界面混语）；打包了某语言却没有切换入口 |
| 横切轴 | 身份边界（登出/换号后本地状态归谁）、角色权限（谁能到达哪个入口）、离线与重试、并发、数据生命周期（删除/过期/迁移）——逐轴问"哪些面持有这类状态" | 换号后前账号的队列以新账号 token 上传；非管理员能直达管理端点；两端同时写同一资源无冲突处理；删除账号后关联数据仍可查 |
| 旅程 | 三元组 ↔ 界面入口与终态 | 任务清单里的工作在导航里找不到入口；成功后页面没有下一步；失败态没有返回主线的按钮；"提交"后按钮变灰但无任何状态文本 |

**契约 census 与前四镜头不同**：前四是"闻味道"（找**多**出来的坏信号：兜底、吞噬、假数据）；契约
census 是"点名册"（穷举契约面找**缺**的调用）。假成功 / 接线缺口这类"缺了个 server 调用"的缺陷
**没有味道可闻**——代码长得和正确的一模一样——只有点名册抓得到。凡"消灭某一类 / 交付完整性"的盘
问，这条镜头是主力，别当补充。它也是 §1 定面时独立播种 facet 表的首选覆盖法。

**横切轴与契约 census 互补，census 列不出它**：census 走的是入口注册表，横切缺陷不住在任何一个入口里，
住在所有持同类状态的入口的交集上——"按设备不按账号存"的毛病每个 Store 都有一份，却没有一个叫"账号隔离"
的路由。所以横切面由盘问官在定面时从需求与代码观察摆出，`surface_ids` 写它横跨的全部 census 面；
一轴的实例落了 gap，同轴其它面就是"孤例还是一类"的枚举对象。

**旅程镜头不出问题牌**：旅程的问题固定是"J 走得通吗"，用户在 §1b 已经选过；这个镜头的用处是
旅程 gap 之后的纵向发散——卡死点周围还有哪些泄漏点（同一状态的其它出口、反向操作、错误恢复），
以及多条旅程在同一种 `stuck_kind` 卡死时提示"孤例还是一类"。

**无基准模式**：需求基准完全缺失时，需求覆盖、需求跑偏两镜头关闭（报告会声明），
只开集成缝隙 + 细节质量 + **契约 census（不吃需求基准、是纯覆盖式，无基准时反而是主力）** + 旅程（吃的是用户口述意图，不吃需求基准，无基准时反而是主力）。

## 问题牌硬约束（每轮 3 张）

1. **每张牌挂一个泄漏点** — 牌面三要素：问题、触发它的泄漏点、预期照亮哪个面；
2. **必须可实测** — 实测官能翻译成具体动作；"代码质量好吗"这类不可测的题不许出；
3. **3 张覆盖不同泄漏点** — 不许全戳同一疑点推销自己的怀疑；
4. **UI/流程牌注明状态清单**（加载/空/错误/成功…）→ 实测官逐状态截图。

一问挖出缺口后，下一轮从该缺口继续发散。发散有两个方向，别只走第一个：
- **纵向**（顺同一条线追后果，出牌）：幂等没做 → 并发双击呢？重试队列会放大它吗？
- **横向**（同类位点清点，不出牌）：这个端点缺幂等 → **其他写端点也这样吗？**走 skill 的
  "孤例还是一类"路径——建 pattern、派枚举官按覆盖法列出全部同类位点、逐个点名清账。
  整族缺陷靠碰巧出对一张牌才被抓到，就是只纵不横的代价。

用户随时可以插自己的问题——牌是引导，不是限制。
