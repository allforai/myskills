# meta-skill：局部需求确认后进入范围匹配的工作流

## Parent

## What to build

交付一条从 bootstrap 收集局部新增功能／修改目标，经必要的需求确认和影响分析，到生成可执行、可验收工作流的完整路径。同时明确产品重塑、局部修改、新建产品三种目标路由；检测到已有代码或缺少产品文档都不能单独触发全量逆推。

本票保留原第 1/6 个纵向切片，包含必要的合同、交互／执行接入与行为测试，不拆成横向层次任务。只实现本票边界，遵守父规格的范围限制。

## Acceptance criteria

- [ ] 同一个 bootstrap 入口按用户目标区分产品重塑、局部需求、新建产品；含糊时仅澄清必要目标，不替用户扩展范围。
- [ ] 对于有代码但没有产品文档的局部功能请求，只分析与任务有关的代码和产品问题，不自动执行全量 reverse-concept。
- [ ] 局部需求的目标、业务规则、验收条件及必要用户决定被记录并可追溯；不全量逆推不等于不建立需求依据。
- [ ] 已有确认决定按适用范围复用；新增或变化的需求明确确认后进入已有产品基准或局部需求记录，不默认为用户接受。
- [ ] 生成的 workflow 与 Node-spec 能表达相关实施、文档和验证责任，并保留无关产品方向和既有工作；不是只输出分类标签。
- [ ] 产品重塑与新建产品被路由到各自流程而不冒充已经完成产品确认；本票不以局部路径替代完整产品发现。
- [ ] 遵守 ADR-0001 的自由规划、Suppress rule 和交互前置，不增加固定通用节点菜单或无人值守访谈。
- [ ] 通过 bootstrap 输入／输出行为场景覆盖有文档的局部需求、无文档的局部需求、产品重塑和新项目路由；Claude、Codex 语义一致。复用现有校验与 fixture，不仅断言提示词文本。
