## Anonymous Meta-Skill Feedback

Category: run-engine
Meta-skill version: unknown

### Failure Pattern

A node whose own repair pass registered reads (files produced by other workflow nodes days earlier) after it had published evidence was reported as an external source change: detect_external_changes compares record inputs with current extra reads, so a read added after publication shows as 'added' source that flow_written does not recognize. Readiness then blocked the whole run with unverified_external_change; running external-changes classified it product-conflict only because the node's acceptance asserts its record status is passed while the record was legitimately blocked on an upstream contract gap. accept requires intent actions, reject and defer both stay blockers, and the node cannot rerun to clear it: a deadlock that needs the user for something that is not a product decision. Worked around by withdrawing that node's obsolete evidence record. Also recurring: parallel waves fail the independent gate with 'Inputs changed during freshness evaluation' (shared observed-input-dependencies.json rewritten by siblings); 4 passed nodes hard-failed. The gate should wait for a quiet tree or lock instead of failing.

### Expected Behavior

The meta-skill should record or repair this class of workflow issue without exposing project-specific information.

### Suggested Fix

Update the relevant skill, bootstrap rule, validator, or orchestrator helper so future projects do not hit the same failure pattern.
