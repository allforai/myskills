【market-research 节点结论】

一、对机会的判断
1. 现有证据只能支持「机会未被证伪」，不支持 A/B 二者取一。扫描没有产生任何
   能区分 A（报价+开票一体）与 B（追款自动提醒）的证据：无行为数据，两个

   方向性信号，不是结论——无法判断设计师对现有替代是满意还是不满。
3. 因此本节点不投票、不排序。A/B 的取舍应由需要行为级证据的节点裁定

二、竞品结论（逐条标证据等级）
4. 直接竞品 4：仅表面级证据（官网功能列表、定价页、商店一句话、少量公开评价）。
   可写「定位与价格带的重叠/空档」这类表面结论；不能写留存/流失/转化，也无从

5. 间接替代 5：真正含义是「用户今天已经在用某样东西」。满意度和迁移成本＝未知，

   评价抓取/第三方数据）；禁止从定价页或功能列表反推死因。

三、ERCK 边界（对下游最关键）
7. Eliminate/Reduce：在表面级证据上可出方向性草案，标注为草案。
8. Create：每条都是未验证假设。按定位子阶段的口径，「竞品一句话简介里没写」

9. 退出物状态：competitor-analysis.json 可落盘，但每个判断带 evidence_grade 字段；

10. 覆盖度 ≠ 证据强度：三类覆盖＝方法正式度达成；结论确定度未达成。两者都要写进

11. 看板副作用：本结论若以「结论」写入 jingpin 列会触发低保真线框；建议以

12. 路由：不 backtrack 上游（方向候选属于用户）；把「缺行为级证据」作为

## Inherited decisions
- 节点 `market-research`（product-concept Sub-Phase 3），无人值守；entry 由 problem-discovery 满足；退出物 `competitor-analysis.json` + `errc-matrix.json`；是 innovation-exploration 与 user-role-definition 的 entry，也是 positioning 的三个依赖之一。
- 上游已确认候选 A / B 属于用户，不是本节点可改的决策。
- 证据库存被场景固定：只有官网功能列表、定价页、商店一句话、少量公开评价；零行为数据、零路线图。
- 采纳规则（MEMORY）：拟改动先给用户看，确认后才写文件/提交；测试阶段可自行推进。cwd 为 `/tmp/s4-baseline`，即对本能力文件**基线文本**跑一次思维测试。
- 可视化协议：`jingpin` 列第一张卡片写入即触发低保真线框。

## Diagnosis
- 这是一个「覆盖度 vs 确定度」陷阱。基线文本对 market-research 的硬要求是**广度**（直接/间接/失败三类都要覆盖），对**证据深度与结论分级一个字都没有**；而同一文件的 positioning 子阶段却明确写着「竞品一句话简介里没有 ≠ 竞品没有」「未核实的差异化点比明说的缺口更糟」。两处标准不一致，基线文本因此允许一个形式合规的市场调研节点输出自信的 ERRC/竞品裁决，而它实际没有支撑。
- 这正是待落地的 S4 候选（方法正式度 ≠ 结论确定度）所针对的形态；本次基线运行**复现了该缺口**：诚实输出需要靠执行者自觉，文本不强制。
- 另一处悄悄假设：problem-discovery 的验收已要求每个情境带 cause 或显式 cause unknown，但 market-research 段完全没把这条继承过来——失败产品的死因推断最容易在这里被凭空补全。

## Drift / contradiction check
- 与能力文件自身冲突：若本节点把 Create 条目当结论交出，positioning 会把未核实差异化点当已定论，直接违反文件里 positioning 的验收条款。所以诚实输出必须把它们标成 hypothesis。
- 与编排器冲突：写 `jingpin` 会触发线框，等于把 provisional 当 settled。建议未定。
- 无其他漂移；A/B 方向未被动过，未偷偷替换上游决定。

## Recommendation
- 采用上面这份**分级诚实结论**作为一次性产出：不重选 A/B、不 backtrack、只把「证据等级 + 未知项 + 缺口路由」作为本节点退出契约。这样下游拿到的是一张可被升级的证据地图，而不是一段会被当已定论的漂亮话。
- 是否把「结论确定度必须与方法正式度分开记录」永久写进能力文件（即正式采纳 S4），是**用户的采纳决策**，不是子代理可以自己定的；按采纳规则，先给用户看拟改动再动文件。

## Risks
- 若 evidence_grade / hypothesis 不进 artifact schema，下游仍会把广度读成确定度。
- `jingpin` 写入 + 线框触发这一副作用可能已经发生或即将发生（协议不改就自动触发）。
- 「间接替代 5」这条信号极易被过度解读为「市场已被满足」，实际不支持该含义。
- 失败产品死因若被后续节点从存档页反推，会成为整条链路里最难发现的假事实。

## Need from main agent
- 本节点能否以 **provisional + 分级** 状态发布结论（以及是否要在本节点抑制 `jingpin`/线框触发），还是必须先补用户侧证据再发布？这是本节点唯一悬而未决的编排层决定。
