# Root Orca dispatch contract

Workflow revision2; spec2/task1 unchanged. Root uses Orca, not run_layers.py. Before every builder, evaluator, supervisor or review dispatch, run controller.py assemble for that task and role. It checks the frozen document hashes and emits a prompt binding the exact task section, complete source snapshot (including comments), program/module contracts, catalog, failure contract, required scenario matrix, and artifact contract. Append the assigned worktree and fixed candidate/base commits. Persist the assembled payload under reviews/dispatches before launch. Missing or changed bindings block dispatch and require projection regeneration/revalidation. Supervisors and reviewers receive these inputs and repository state, never builder narrative.

Subjects use a separate raw-scenario dispatch: synthetic fixture, explicitly resolved candidate Skill path, current user turn and side-effect boundary only. Never give subjects task packets, source issues, this contract, evaluator criteria, or prior verdicts. Root records actual host, resolved candidate loading and output evidence independently.

## Role-aware admission

Cap3 includes builders, evaluators, subjects, supervisors and both review axes. At most one evaluator is admitted at a time. An evaluator may be admitted only if one additional slot remains for its subject. While an evaluator is live, ordinary builders cannot consume the last reserved slot. Subjects and completion reviews have priority over new ordinary work. Settled workers are released before dependent reviews/subjects are admitted. A settled builder never waits in its worker slot for its supervisor; the root queues that candidate and releases the builder first. Both review axes start together when two slots are available; a sole evaluator may remain live while that pair runs, but its subject requests wait for a finite review completion, not another waiting evaluator. Real physical resources still require their named mutex.

controller.py admission and dry-run implement these predicates. Root consults them before every worker launch, and persists actual admission/verdict/release/merge events. No task dependency edge is added for capacity. A ready evaluator may wait while finite autonomous builders finish; root prioritizes its pending subject as soon as admitted. This prevents the T15/T16/T17 evaluator hold-and-wait cycle without raising the cap.

## Completion and recovery

Follow catalog gates: TDD builder -> fresh acceptance supervisor -> independent Standards and Spec -> serialized integration -> post-merge focused acceptance -> confirmed marker. Each task's frozen acceptance command is necessary, never sufficient alone. Scenario acceptance additionally requires every matrix cell on both actual candidate-loaded hosts, complete dialogue/tool/artifact evidence and current relevant input identity. An unavailable or stale cell remains unverified. Scope/authority, two infrastructure retries, two business retries, owner-directed repair, transitive skips and unrelated progress remain as frozen in concurrency rules. No tracker edits, pushes, installed updates or main worktree writes.
