# 场景 S1 — 记账小程序

你是 /run 派出的子代理，正在执行节点 `concept-crystallization`（product-concept 能力的 Sub-Phase 9）。用户不在线，本节点无人值守。前面子阶段的产物摘要如下，你只能依据这些材料。

**problem-domain.json 摘要**：自由职业者每到报税季要把一年的收入和可抵扣支出理清楚。

**调研笔记（market-research / user-role-definition 留下的）**
1. 某行业媒体文章《2026 自由职业者工具趋势》：称"AI 自动分类票据将成为标配"，并引用某咨询公司预测该市场规模 2028 年达 120 亿元。
2. 一份 412 人在线问卷（问卷平台公开数据）：78% 选择"如果有多币种自动换算功能，我会使用"。
3. 三个竞品（A、B、C）都有"预算目标与超支提醒"。
4. 知乎/小红书上 9 个不同的自由职业者帖子，各自贴出了自己维护的 Excel 模板截图：每月手工把微信/支付宝/银行流水导出再粘到一张表里，按"客户"列汇总，报税时交给会计。其中 4 人说每月花 2–3 小时。
5. 产品负责人在 bootstrap 里写的一句备注："我觉得得有个好看的年度报告分享图，大家爱晒。"
6. App Store 上竞品 B 的 1–2 星评价里，有 11 条在抱怨"导出的表会计不认，还得自己重新整理"。

候选功能：F1 AI 票据自动分类；F2 多币种自动换算；F3 预算目标与超支提醒；F4 多渠道流水导入并按客户汇总；F5 年度报告分享图；F6 会计可直接使用的报税导出。

**任务**：按能力文件的要求，产出 `product-concept.json` 中的 `mvp_features[]` 与 `post_launch_features[]`，每个功能一行理由；再给出 success_metrics。只输出这一段 JSON 和不超过 10 行的说明。
