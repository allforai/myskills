Category: run-engine

### Failure Pattern

0.29.0: a node re-dispatched with .allforai/bootstrap/diagnosis-corrections/<node>.json registers that file through the freshness read operation (the engine tells it to read the file). On completion the engine deletes the file, so the node's just-published evidence is stale ('changed'), downstream QA that passed cannot publish, the engine treats the QA as failed, routes the declared repair loop (unmeasured_repair_delivery) and ends needs_diagnosis; readiness then reports unverified_external_change and requires interactive bootstrap. Every diagnosis-driven rerun therefore dead-ends. Suggest excluding diagnosis-corrections/** from freshness reads, or not deleting it.

### Expected Behavior

The meta-skill should record or repair this class of workflow issue without exposing project-specific information.

### Suggested Fix

Update the relevant skill, bootstrap rule, validator, or orchestrator helper so future projects do not hit the same failure pattern.
