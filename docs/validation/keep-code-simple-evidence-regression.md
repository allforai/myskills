日期：2026-09-10。承接[三端原生验收](keep-code-simple-native.md)发现的两项报告质量问题。

## 修改边界

仅修改共用协议中两处规则，再由 `sync.py` 同步三端包内副本：

1. 安全发现区分源码事实、未知外部条件、可能后果；结论不确定不降低资金/数据风险的优先级。
2. `resolved` 只接受宿主 metadata/receipt 并引用出处；无证据为 `unknown`，调查员自报单列 `self-reported`。

没有新增调度器、报告台账、审查阶段或中途问题；未修改平台入口或运行权限。

## 有界修订与第二轮

在原有安全发现段落内补上逐条反例检查：**未查的外部实现能否使后果不成立？** 能则必须写明必要前提，不能只加“若”或一个条件性标题；给出网关防重与账本副本两个简短示例。

这仍是原来的合并过滤规则，不新增调查任务或审查轮次。只对同一 Claude 原生协议做一次新的隔离回归，源 fixture、调用命令及权限不变。前述三个思维测试对应首版协议，不伪称已在最终修订上重跑。

### 第二轮结果：部分通过，停止继续堆规则

12 个契约测试 + 8 个既有回归再次通过。Claude 约 436 秒完成，三路 Agent 实际派发；转发消息中的型号为 Opus ×2、Sonnet ×1。源文件摘要与集合未变，唯一项目写入是报告，测试执行 marker 不存在。一次调查员请求的只读 Git/目录查询被宿主以 `Bash is disabled for this session` 拒绝，未执行、未换模式；其他可见调用为读取与搜索。不能将该轨迹描述成“完全没有工具失败”。

| 检查 | 结果 |
|---|---|
| resolved 无宿主证据时 unknown，自报单列 | 通过 |
| F2 明确网关可能按发票防重 | 本反例通过 |
| F5 明确账本索引可能返回副本 | 本反例通过 |
| 所有安全后果均列齐必要前提 | **未通过** |

仍有残余推断错误，不能宣称报告可靠性已彻底修复：

- **F3** 把调用方放弃重试写成“永久不可对账”，没有排除外部对账/恢复作业；只读局部函数不能证明永久不可恢复。
- **KEEP-1** 把请求键幂等称为“唯一”防重保护，与网关可能另有发票级防重的未知条件不一致。保留防护的建议合理，但其理由过强。
- **反面清单** 将 `ledger.get(k) or {...}` 与 `setdefault` 的实参预求值一起否决；Python `or` 会短路，不能据此断言右侧总会执行。这是额外的技术推理错误，不属于模型溯源问题。
