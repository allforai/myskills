| 模式 | 契合度 | 说明 |

| 路由不许只给裸指针：被指能力不可用时内联最小版本 | 契合 | product-review 已这样做 |
| 短而判断密集；裁剪判据="删掉这段，模型判断会变差吗" | 契合 | 可用于瘦身 product-concept（485 行里 client_type 表等属 schema，不属判断） |
| 讲原则同时讲它的误用边界 | 契合 | product-review 的镜头段（"镜头不是清单"）已是此写法 |
| CI 只强制可机械判定的契约，判断质量走 advisory 评测、不作合并门 | 契合 | 与现有 validator 边界一致 |
| Clarify First + 止损（用户说随便 → 列假设继续）；问题预算 | 部分 | 已有"一轮问完、带推荐默认"；预算概念可借 |

## 四、明确不借的

- 框架背诵类（SWOT、PESTEL、Porter 五力清单、RICE 公式本身、Lean Canvas 九格）：强模型本来就会，写进去只增重。
  product-concept 现有的 "Theory anchors" 多半属于这一类——锚点名字留着无害，但它们不产生判断。
- 依赖真实用户与线上数据的部分：访谈脚本、A/B 统计、留存曲线形状判读、OKR 评分。管线在上线前运行，够不着。
- 产出型模板（PRD、用户故事、周报、路线图沟通）。
- 增长/成瘾机制（Hook 模型）作为设计目标：来源自己也带伦理警告；只保留其"回来的理由"判断，而这已有（`return_reason`）。
