## 两处落地

**`79a421d2`（21 行，Sub-Phase 1 + 5）**：问题陈述、机会树每个节点、每条 job，读起来必须是一个人身上的处境；
读起来是一个能被建造出来的东西（功能名、界面名、机制名）就是方案，不能放在这一层。用户开口就给方案时，
把方案记为"用户提出的候选方案"挂在处境下面，并把"为什么会这样"留成要问用户的问题。

**`56fc766e`（19 行，Sub-Phase 8）**：价值主张与定位陈述各过三问——换成大白话除了品类还剩什么；会不会有正常
竞品宣称相反的话（没人会这么说，就什么都没排除）；上游点名的竞品能不能原样贴到自己首页。三问任一不过就不是
定位。上游本身含糊时，`positioning.json` 如实写 `status: "not_differentiated"` + 缺的那个事实 + 归谁补，而不是
用措辞盖过去。

这条改动本身经过了两轮收敛，值得记下来：
- 第一版（17 行）跑 GREEN，两遍都只改善一半——它把竞品的一句话简介当成"核对过"，
  还自己造了一个 `partially_differentiated` 状态。
- 补两句后（"核对过"必须有出处表明竞品确实没有；`status` 只能取两个值，未核对的差异点写 `not_differentiated`
  并附最好的草稿）再跑 GREEN2，达标；同时跑 S4 回归确认上游明确时不会被误判。

## 该记住的两件事

- **"现状没有"这个判断容易下早。** 第一轮结论是 S1/S2 需要改，理由是文件里没有证据分级表；实测发现一条已有原则
  （Mom Test）就带出了正确行为。**先跑基线，再提改动**——这是这轮最有价值的产出，比那 40 行代码更值。
- **共享工作区里不要跑影响整个工作区的 git 命令。** 那次会话排查测试时执行了一次 `git stash`，而另一个会话
  正在同一仓库的 `fix/run-loop-deadlocks` 分支上改 10 个文件（已 `stash pop` 复原，无丢失）。当前分支不是 main 时，
  用临时工作区提交到 main。
