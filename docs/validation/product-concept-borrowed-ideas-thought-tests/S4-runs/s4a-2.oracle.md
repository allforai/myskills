**market-research 节点结论（S4a，无人值守）**

一、对机会的判断
- 搜索方法层面：直接 4 / 间接 5 / 失败 3，三类覆盖齐全，**方法正式度**已达标。
- 但结论置信度不得随方法完整度一起上升：每个竞品只有官网功能表、定价页、商店一句话、零星公开评价；**无留存 / 流失原因 / 付费转化数据，也无内部路线图**。
- 本次可判定的：功能与定价的**表层差异**（谁做了报价+开票一体、谁的定价档位、谁提供提醒）。
- 本次不可判定的：失败原因、付费意愿、迁移成本、留存——记 `unknown`，**拒绝**从"覆盖了失败类别"推因果。
- 3 个失败产品：仅 1 个官网存档页 + 2 条论坛帖，cause 记 `unknown`，并注明来源缺口。
- 上游候选 A「报价单+发票一体」、B「追款自动化提醒」是**方案形态**；本扫描只能答"有没有竞品在做"，不能答"用户是否要"。方向取舍交回上游/用户，本节点不代为决定。

二、竞品结论（含 ERRC）
- 竞争地图：写清谁覆盖哪些环节、处于哪个定价档；**"不在竞品一句话简介里" ≠ 竞品没有**，未核实就不写进结论。
- ERRC 各格只在有来源支撑时填写；无来源的 Eliminate / Create 格留 `unknown`，不填占位句充数。
- 强弱项判断只认有评价支撑的部分；其余标为"资料不足"。

三、对编排器与后续节点的记录
- 产出 `competitor-analysis.json`、`errc-matrix.json`；每条主张带 `source` 与 `confidence`（表层证据=低/中）。
- 给 positioning 的护栏：若据本节点**未核实**的差异点立定位，必为 `status:"not_differentiated"`，并注明缺失事实与负责子阶段。
- 未决项（不静默决定）：失败原因、付费意愿、A/B 倾向，均记为待验证。

Oracle 一致性提示：本场景的要点就是 S4——"扫描步骤跑全了"证明的是方法正式度，不是结论确定度；上面把二者分开记账，与本轮已落地的"定位空话检测 / 不可从一句话简介推缺失"规则一致。若这个节点被要求输出高置信的失败归因或方向选择，那是漂移，应打回而不是补话术。
