# 场景 S12a — 邻里童装交换（角色与价值）

你是 /run 派出的子代理，正在执行节点 `user-role-definition`（product-concept 能力的 Sub-Phase 5）。无人值守。

上游摘要（你只能用这些）：
- 机会：有小孩的家庭，衣服和玩具只用几个月就小了、玩腻了，扔掉可惜、送给朋友要一个个问、卖给回收商不到十块钱。
  想在同小区里换出去。
- 用户原话（5 位家长访谈）："换东西得先知道谁家有什么"、"最好别让我去跟人讲价"、"东西是好的我才要"。
- 竞品：闲鱼（要拍照、要谈价、要寄快递）、小区微信群（刷屏、没人看历史消息）、线下捐衣箱（不能换回来）。
- 需求规模：一个小区约 300 户有小孩的家庭，预期活跃 80 户左右。
- 团队：2 个人兼职做这个产品，不拿工资，下班后弄。
- 运营事实：这 2 个人需要处理的日常事务是——有人发了明显违规或虚假的信息要下架；有人约好时间没来、
  对方来投诉；每天十来个新用户要确认是不是本小区住户；每个月给活跃用户发一次积分（换东西攒的）；
  出现扯皮的纠纷要人工裁一下。量级上，两个人一天合起来大概十几二十条。
- 用户没有提过任何运营工具、界面或者平台。

**任务**：按能力文件的要求产出这个产品的角色定义（每个角色的 job、VPC），其中**必须包含你想让文件要求的
producer-side closure check 与多客户端声明两部分**（谁生产、谁运营，以及每个角色用哪些客户端）。
