# 扫全实测官（sweep）— 固定 question 模板

扫全模式把同一句 question 盖到每一个操作面上，这句话就是覆盖模板：漏一个观察口，所有面一起漏。
所以它不即兴写。派发 = prober.md 全文 + 本文件全文 + 输入 JSON；纪律与返回合同都沿用 prober.md。

## 输入合同（在 prober.md 的合同上只改 question 与 states_to_capture）

模板按面的种类分三个变体，盘问官只选变体、不改措辞。三个变体的 03/04 完全相同；00/01/02 是同一个不变量
（触发前 / 触发中 / 触发后）在不同介质上的说法。**00/01/02 没有"不适用"出口**：一个面既没有界面、也没有命令、
也没有可读的资源状态，那它就不是一个可触发的操作面，退回给盘问官重新定面，不要用"不适用"填坑。

**变体 A · 界面操作**（用户点得到的按钮、表单、手势），`question`：

> 触发 <surface id>「<surface name>」（入口 <entry>）后实际发生了什么：触发前、触发中、触发后界面各是什么样；
> 触发期间出现了哪些请求或外部调用（方法、目标、请求体摘要、状态码、响应体摘要；零条就记零条，并记下
> 你用什么手段抓的、同一会话里它抓到过哪条别的请求）；
> 触发后该操作对应的服务端资源和本地存储各读回来是什么（只涉及一边的，另一边写"不适用"并说明为什么）。

```json
["00-触发前初始态", "01-触发中（加载/等待/禁用态，一闪而过也截）", "02-触发后界面态（提示、跳转、无变化，如实记）",
 "03-请求记录（抓取手段 + 同会话已抓到的任一其它请求 + 请求去向 host/进程/拦截层 + 触发前后请求列表原文，文本文件）",
 "04-后置数据（服务端资源与本地存储各自读回原文，不涉及的写不适用，文本文件）"]
```

**变体 B · 命令与接口**（CLI 子命令、HTTP/RPC 端点），`question`：

> 调用 <surface id>「<surface name>」（入口 <entry>）后实际发生了什么：调用前的相关状态、调用的原始输出或响应、
> 调用后的相关状态各是什么；
> 调用期间出现了哪些下游请求或外部调用（方法、目标、请求体摘要、状态码、响应体摘要；零条就记零条，并记下
> 你用什么手段抓的、同一会话里它抓到过哪条别的请求）；
> 调用后该操作对应的服务端资源和本地存储各读回来是什么（只涉及一边的，另一边写"不适用"并说明为什么）。

```json
["00-调用前状态（相关资源/文件/表的读回原文）", "01-调用输出（stdout/stderr/响应体原文与退出码或状态码）", "02-调用后状态（同 00 的对象再读一次）",
 "03-请求记录（抓取手段 + 同会话已抓到的任一其它请求 + 请求去向 host/进程/拦截层 + 调用前后请求列表原文，文本文件）",
 "04-后置数据（服务端资源与本地存储各自读回原文，不涉及的写不适用，文本文件）"]
```

**变体 C · 后台任务与消费者**（定时任务、队列/事件消费者、钩子），`question`：

> 让 <surface id>「<surface name>」（入口 <entry>）跑一次后实际发生了什么：你用什么手段让它跑起来（直接调入口函数、
> 改调度表达式、往队列投一条消息、发一个事件——手段本身是观察，照实记）；跑之前它作用的资源是什么状态、跑的
> 过程中进程输出了什么、跑完之后资源是什么状态；
> 跑的期间出现了哪些下游请求或外部调用（方法、目标、请求体摘要、状态码、响应体摘要；零条就记零条，并记下
> 你用什么手段抓的、同一会话里它抓到过哪条别的请求）；
> 跑完后该任务对应的服务端资源和本地存储各读回来是什么（只涉及一边的，另一边写"不适用"并说明为什么）。

```json
["00-运行前资源状态（它会读写的表/文件/队列的读回原文 + 你选择的触发手段）", "01-运行期间进程输出（日志/stdout 原文，含开始与结束的痕迹）", "02-运行后资源状态（同 00 的对象再读一次）",
 "03-请求记录（抓取手段 + 同会话已抓到的任一其它请求 + 请求去向 host/进程/拦截层 + 运行前后请求列表原文，文本文件）",
 "04-后置数据（服务端资源与本地存储各自读回原文，不涉及的写不适用，文本文件）"]
```

## 三个观察口，一个都不能省

界面反馈、请求记录、数据读回并列。请求记录里"零条"只有在同一份文件能证明抓取手段活着（同会话抓到过
别的请求）时才是观察；抓取手段没抓到任何东西，写 `could_not`，不写零条——"没发请求"和"没抓到"是两件事。
数据读回两边各读一次：只读本地会让"写了本地、该上传却没上传"的操作看起来三面一致。

盘问官事后对着三面裁"契约是否兑现"：三面一致才是 done；界面报成功而请求为零或数据未变，是假成功；请求已落而界面无反馈，是反向的接线缺口。
你只带回三面，不判哪一种。

## 与 prober.md 不同的两点

- 五个状态对应五个证据文件，缺一个就是"返回残缺"，会被同一输入重派。某个状态真的取不到（任务起不来、
  日志没有输出）就在该状态的文件里写清楚试了什么、卡在哪，并进 `could_not`；不写"不适用"。
- 前置条件（登录态、需要先有的数据）由你自己造；造不出走 `could_not`，不绕。
