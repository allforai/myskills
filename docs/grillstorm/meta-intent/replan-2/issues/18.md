## What to build

分别走通外部改动从发现差异到用户决策、传播、修复／同步、验证及恢复的完整路径，每条路径必须落在有证据的完成或有明确原因的受阻状态。

这是保留的补充思维测试批次 4/4；目标是实际执行并验证 Skill 决策，而不是只写测试计划。场景判据属于评估侧，不得整份票据连同预期结论直接交给受测 agent。

## Acceptance criteria

- [ ] 外部修改仅改变实现细节：验证识别后增量更新事实文档，不无故启动全产品访谈，不改写产品意图。
- [ ] 用户接受外部行为变化：验证决定与理由记录、基准更新、受影响任务／文档协调、证据重验以及恢复执行逐步发生。
- [ ] 用户拒绝外部行为变化：验证保留原基准，形成明确修复任务；恢复预期行为并同步、重验后才允许完成。
- [ ] 用户暂不决定：验证保留冲突和恢复上下文，相关工作受阻，无关工作不会被全量重置。
- [ ] 在冲突处理过程中中断后续接：验证已做决定不丢失、不重复问，未做决定不被补造，能够接续正确的接受／拒绝路径。
- [ ] 无人值守过程中发现产品冲突：验证不发起产品访谈、不默认接受变化，不用新代码覆盖产品基准；后续回到交互入口解决，再完成恢复闭环。
- [ ] 只更新了差异报告但没有同步、修复或有效重验：验证不能判完成；系统明确剩余步骤与责任，而不只是留下差异。
- [ ] 对已完成恢复的同一输入再次运行：验证结果稳定，不重复创建决定、修复任务或触发新的伪漂移。

### 执行、证据与关闭条件

- [ ] 以独立、干净上下文执行每个场景；受测 agent 仅接收场景、原始仓库／历史资料、当前 Skill 和该步用户输入，不接收判据、预期结论、怀疑或其他测试报告。预定中断续接场景仅传其应有的持久化状态。
- [ ] Claude、Codex 分别实际执行；记录平台、被测版本、独立会话身份、场景输入、逐轮问答、工具行为、生成产物及状态变化。没有相关能力或未执行的平台标为无法验证，不以另一端结果代替。
- [ ] 评估侧单独持有逐场景判据，并用实际问答、产物、差异和执行状态判断通过／失败／环境无法验证；不能用提示词含关键字、文件存在或 agent 自报代替行为验证。
- [ ] 使用隔离测试项目和合成数据，不影响真实产品、不开展生产调用、不安装无关依赖或重写产品需求；优先复用已有 fixture 与校验边界，不新建独立测试框架。
- [ ] 失败场景记录最小可复现步骤、输入／版本、观察与预期差异，并创建或关联责任缺陷及对应实现票。已有关联缺陷则复用，避免重复。
- [ ] 缺陷修复后使用新上下文复测受影响场景并记录前后证据；只修改一句提示词或创建缺陷票不能关闭本测试票。所有必测场景在两端验证通过才完成，未解决失败或环境无法验证须保持未完成并明确原因。
