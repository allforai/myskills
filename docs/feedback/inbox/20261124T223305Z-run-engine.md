## Anonymous Meta-Skill Feedback

Category: run-engine
Meta-skill version: unknown

### Failure Pattern

Declared repair loop: a repair node's edits to shared source (client/**, server/**) make already-completed upstream nodes (sibling QA in the same tier, the previous tier's repair node, build-verify) stale. Delivery measurement requires withheld_by to be only the loop's own open QA nodes, so every real repair is measured as unmeasured_repair_delivery and burns attempts; the engine never reruns stale completed nodes inside an invocation (only inherit checks at startup), so the orchestrator had to stop, reconcile the interrupted grant and restart 3 times. Suggest: after a repair delivers, re-run (or republish) every completed node whose evidence the repair made stale before measuring, or accept withheld_by from nodes whose staleness is caused by the repair's own write scope. Also: vitest caches under client/node_modules count as source in freshness and surface as unverified_external_change; exclude node_modules. And: a repair record that lists known_limits is refused (no limited_statuses), while listing them in code_gaps fails status — repair nodes need a declared way to report residual issues for QA to judge.

### Expected Behavior

The meta-skill should record or repair this class of workflow issue without exposing project-specific information.

### Suggested Fix

Update the relevant skill, bootstrap rule, validator, or orchestrator helper so future projects do not hit the same failure pattern.
