## Anonymous Meta-Skill Feedback

Category: convergence
Meta-skill version: 0.20.1

### Failure Pattern

run-engine 声明式修复回路死锁：repair 节点修改了已完成上游节点的产出（spec 文件）→ 上游证据 stale；repair 节点 publish 要求上游 valid 且被本回路 QA（未重跑的 critique）挡住；repair agent 报 soft_fail 而非交付，引擎结算为 failed，3 次预算全部耗尽，但规格实际已修好。建议：(1) repair 节点规范要求重新发布被其改动的上游节点；(2) engine 把“只被本回路 QA 与被本 repair 改动的上游挡住”识别为交付；(3) 节点不得通过 freshness read 登记 .allforai/bootstrap/workflow.json 等编排状态文件（ia-design 这样做导致每次提交都使其证据过期）；(4) 重新 bootstrap 时清理与新计划冲突的 observed-input-dependencies；(5) 第二轮引擎 ledger:consumption 代理返回 'invalid — list index out of range'，直接调用 repair_authorization.py consumption 可正常返回 ok，疑为代理调用方式问题。

### Expected Behavior

The meta-skill should record or repair this class of workflow issue without exposing project-specific information.

### Suggested Fix

Update the relevant skill, bootstrap rule, validator, or orchestrator helper so future projects do not hit the same failure pattern.
