## 方法

- 场景两个，各跑两遍，共四份；**两种只读代理各跑一遍全场景**（`reviewer` 四份、`oracle` 四份，见下"宿主侧说明"），
  所以同一场景实际有四种独立上下文。
- 受试只读两个文件：`product-concept.md`（被测文本）与场景包
  [scenarios/s4a.md](scenarios/s4a.md) / [scenarios/s4b.md](scenarios/s4b.md)；
  包哈希 `c6f92eef…` / `e2312300…`。
- 判据运行前写下：
  - **S4a（扫描充分但只有公开简介，局面结论薄弱）**：把"我扫了什么、覆盖度如何"与"因此能断言什么"**分成两句**；
    写明这份材料**不能**说明什么（无行为数据、无内部路线图）；不把"竞品一句话简介里没提"升级成"竞品没有"，
    更不据此宣称"我们做就能赢"；未核对项路由出去，不自行补齐。
  - **S4b（有真实行为证据·对照）**：照常**果断给方向结论**，用证据分级而不是把一切包进"不确定"；
    边界照写但不淹没结论；不把"品类有人付费"读成"这个机会成立"。
- 原文逐份收在 [S4-runs/](S4-runs/)（保留目录里的宿主产物，未经改写）。

## 宿主侧说明（本轮的两个环境事实）

1. **`pi-subagents` 0.70.0 的 `reviewer` 在本机不可用**：它的 frontmatter 现在声明
   `tools: read, grep, find, ls, watchdog_diff, contact_supervisor`，而 `watchdog_diff`
   只在 watchdog 功能启用时注册（实现见包内 `src/watchdog/diff-tool.js`）。于是四条 `reviewer`
   派发都在预检被拒：`Agent 'reviewer' requested unavailable child tools: watchdog_diff`。
   四条其实是**先写完了答卷、在收尾步骤才判失败**，产物落在
   `~/.pi/agent/sessions/…/subagent-artifacts/`，已原样收进本记录。
   影响面不止本轮测试：Pi 侧的 cross-exam / keep-code-simple 都把 `reviewer` 列为候选只读代理，
   在本机一用就死。修法：(a) 改用 `oracle`（本机可用、同样只读）；(b) 在 settings 里启用 watchdog
   让该工具注册。本轮先用 (a) 复跑，因此同一场景有 reviewer/oracle 两套答卷。
2. **升级前的旧 Pi 进程里，async / workflow 派发全废**（`Cannot find module …/subagent-runner.ts`，
   因为包已由 `.ts` 改为 `.js`），重启后恢复；本轮的后台 workflow 是重启后才发得出去的。
